# Mandatory execution contract — 525
## Goal
Reproduce original/reissue 500-series 525, not 525A. Build a complete component-level ngspice reference first, then a lightweight Windows x64 VST3 named 525. Target <=5% error; 5–10% allowed only as individually documented exceptions; >10% fails. Never confuse model-to-model agreement with physical hardware accuracy. Do not stop at a plan, prototype, screenshots or partial netlist. Work through failures, record evidence, resume from checkpoints. Do not fabricate data, sources or pass results.

## Gate 1 — source and entire circuit (before ANY simulation)
1. Obtain the exact revision schematic, BOM, board photographs, switch wiring, transformer details and manufacturer test methods. Cross-check historical 525C schematic against 2020 reissue, which uses 2510 and 2520 and has relay bypass. Do not silently equate them. Record revision differences, conflicting component values and missing evidence. If only vintage circuit can be substantiated, label it accordingly and do not certify exact reissue. Seek service documents and physical measurements as necessary.
2. Create a pin-by-pin BOM and connectivity ledger (reference designator, value, tolerance, nodes, polarity, model source, revision, verification). Trace every resistor, capacitor, diode, transistor, FET, transformer winding, pot segment, stepped ceiling resistor, switch contact, relay, meter loading, trim, protection/decoupling part, link/mono strap and connector. Include detector sidechain and its transformer if present in chosen revision. Fixed ideal +/-15 VDC at supply entry is the only authorized PSU simplification; retain on-board supply circuitry. Model balanced source and load. Use actual potentiometer taper or measured law, actual detents and contact truth table. No guessed topology or dummy stages. Validate against schematic visually twice; compare flattened netlist and BOM counts, node degree, pin mappings, polarity, switch truth table and floating nets. Complete entire connected netlist before .op, AC or transient runs, including discrete op-amp interiors. No stage-by-stage simulation while wiring is incomplete.
3. Locate existing 2520, 2510 and Jensen 990 SPICE models; inspect actual internals and compare to appropriate schematics. Reject ideal op-amps, generic behavioral surrogates and models with hidden unverified topology for reference. If no trustworthy complete model, reconstruct every internal resistor, capacitor, diode, transistor, inductor and other component, including bias/compensation/output protection. Record device pinouts, manufacturer models, selection and tolerances. 990: use documented original JE-990 at +/-15 V, distinguish 990A/C revisions. Replace only the documented 2520 positions for alternate mode, retain native 2510; verify pin compatibility, bias, stability, current and loads. If historical circuit contains several 2520s, switch all applicable positions together and document them. Do not imply 990 is factory option.
4. FET: identify exact device and polarity, fit Id/Vgs/Vds, pinch-off, leakage, capacitances and triode resistance from reliable curves or measurements. Include gate bias, nonlinear channel distortion and circuit linearization. Transformers: use actual winding configuration, ratios, DCR, leakage, magnetizing inductance, winding capacitance, core loss, saturation/hysteresis and loading; measure or substantiate parameters. Never add an input transformer to a revision with active balanced input. Do not use ideal transformer alone or a generic saturation curve as validated reference. Keep uncertainty ledger and source provenance/licensing.
5. Gate artifact: full schematics/netlists, BOM coverage report with 100% mapped components, source ledger, switch table, pin audit. No simulation until full circuit is connected and reviewed. Unresolved values must be explicit; no claimed completion with placeholders.

## Gate 2 — SPICE electrical validation
Run standalone op-amp benches after Gate 1, then full circuit. Verify DC operating points, rail currents, offsets, transistor currents/regions, FET bias, detector rectification, capacitors, negative feedback, clipping, source/load stability, relay and every switch combination. Test op-amp open/closed-loop gain/phase, slew, noise, output swing, current limit, common-mode behavior, distortion vs frequency/level/load. Compare to documented tests, not arbitrary targets. Log ngspice version, solver settings, convergence, warnings and raw waveforms. Use timestep convergence and tolerances; fix root causes not symptoms. No artificial shunts or retuning undocumented parts just to force desired output. Re-run impacted tests after every change, version/hash results.

## Gate 3 — exhaustive reference characterization
Execute MEASUREMENT.md across entire control domain for both op-amp types. Verify hardware specifications where comparable; investigate discrepancies by examining nodes, bias, device models, transformer loads and measurement definitions. Preserve all evidence. Do not begin surrogate fit until complete reference matrix and validation are available. Hardware data gaps block claims of hardware equivalence; simulation alone cannot prove exact THD. Document fixed +/-15 V vs factory test rails and revision impact; optionally measure factory supply as separate validation, never silently change requested reference. If hardware capture unavailable, label hardware validation incomplete and do not invent a pass. Maintain checkpoint files and run shards on GitHub Actions; resume failures without discarding raw results.

## Gate 4 — lightweight real-time model
Only after reference characterization, implement JUCE/C++ VST3 using causal reduced-order DSP, not ngspice or full circuit solve in audio callback. Derive feedback topology, FET nonlinearity, detector/rectification, timing states, ceiling interaction, output/sidechain transformer memory, op-amp loading/headroom, noise and phase from measured data. Preserve dynamic distortion, frequency-dependent release, attack overshoot, knee, independent IN/OUT and actual ceiling law. No universal waveshaper or static IR replacing dynamics, no arbitrary THD knob. Fit across entire grid and validate independent off-grid cases; keep separate 2520/990 parameter sets. Use oversampling or internal substeps only where verified necessary (15 us attack is shorter than a 44.1k sample); anti-alias, maintain phase and report actual latency; compare 1x/2x/4x/8x as needed, choose lowest validated cost. No allocations, locks, file IO, network or unbounded loops on audio thread. Automate/smooth pots without corrupting transients; discrete switches must follow hardware truth table and avoid unsafe state jumps. Mono and stereo layouts; default stereo independent hardware channels, optional linked behavior only if original link is verified and clearly located outside faceplate. Persist all settings. Default 2520. OFF keeps signal path; BYP bit-transparent with correct host latency compensation. Meter measures gain reduction excluding makeup and unrelated saturation, follows circuit reference with readable display ballistics.

## Gate 5 — build and proof
GitHub Actions Linux ngspice jobs (sharded, resumable, artifacts) and Windows x64 CMake/JUCE build, pinned tool versions/dependencies and reproducible commands. Implement actual VST3 host runner to load compiled binary, set parameters and render stimuli; compare binary outputs against independent reference, not just DSP source. Run pluginval, smoke/automation/state save and reload, mono/stereo, sample rate 44.1/48/88.2/96/192 kHz, buffer 64/128/256/512/1024, silence/denormals, clipping, real program audio. User baseline Ryzen 7 8745HS, 44.1k/512: block deadline 11.61 ms; aim p99 <=2 ms per instance, no deadline misses; document runner CPU vs actual user PC, do not claim local benchmark without it. Report latency, CPU p50/p95/p99/max, alias tests, memory. Capture actual running editor screenshots, not mockups. Publish downloadable 525-Windows-x64-VST3.zip containing .vst3 bundle, install/readme; release with commit ID, build log, SHA256, reference data manifests, comparison report, raw results and unresolved issues. Do not label final if gates fail; preserve partial artifacts and exact blockers. Do not overwrite unrelated repositories or release assets.
